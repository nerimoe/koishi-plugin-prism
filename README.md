# koishi-plugin-prism

[![npm](https://img.shields.io/npm/v/koishi-plugin-prism.svg)](https://www.npmjs.com/package/koishi-plugin-prism)

**koishi-plugin-prism** 是用于连接 **PRiSM Next** 计费与设备管理系统的 Koishi 机器人插件。它可以替代旧版 `plugin-prism-neo-koishi`，为玩家和店员提供便捷的群内与私聊机器人交互指令。

## 🌟 功能特性

* 🎮 **玩家入场与结算**：通过 `/login` 和 `/logout` 指令开启或结算计费场次，支持 `/入场` 别名；命令回复会引用触发消息，结账账单可私聊通知店员。
* 💳 **账户钱包与资产管理**：支持查询钱包余额（`/wallet`）和持有的道具资产（`/items`）。
* 🀄 **麻将桌位集成**：`/mahjong <桌号>`、`/上桌 <桌号>`、`/下桌 [桌号]` 和 `/麻将列表`。麻将桌是 PRiSM 里带麻将能力的资源，桌名、别名和人数都在网页里设置；上下桌和开局计费全部由平台完成：玩家不必先入场，坐满时平台为全桌同时开始计费，已开局的桌有人补位时立即开始计费。`list` 由平台列出在店的人：每人只列一处，正在占用的资源（麻将桌和其他游戏机一样显示人数和容量，等人凑桌的也在桌上）或最具体的计费方案。Bot 不再在进程里暂存任何桌位，重启不影响。
* 🔌 **硬件设备状态与电源管理**：可直接在聊天中查看设备状态（`/show`）、远程开启/关闭电源（`/on`、`/off`）、远程投币（`/coin`）和模拟刷卡（`/scan`）。
* 🎟️ **礼物兑换码**：使用 `/redeem <code>` 兑换系统发放的福利礼包。
* 🛠️ **管理员快捷指令**：允许管理员为指定平台用户增加或扣除余额，并覆盖结账金额后立即结账。

所有技术异常在聊天中只显示通用失败提示，不会包含后端名称、URL、网络状态、原始 `fetch` 错误或 HTTP 状态。完整原始异常会写入 Koishi 的 `prism` 日志，供管理员排查。

## ⚙️ 配置说明

Koishi 里只填怎么连到店铺：

| 配置项 | 类型 | 描述 |
| :--- | :---: | :--- |
| `baseUrl` | `string` | **必填**。PRiSM Next Server 的访问基准 URL（如 `https://prism-mmw.neri.moe`）。 |
| `shopCode` | `string` | 可选。店铺公开编号；接入凭据已经指明店铺，**不需要填**。旧配置保留也能用。 |
| `integrationToken` | `string` | **必填**。从 PRiSM 网页后台生成的 Integration API 令牌。 |

其余一切都在 PRiSM 网页里设置：每个令牌对应一个 Bot，Bot 在店铺里是一个**资源**。在**商户工作台 → 资源 → 这个 Bot → Bot 设置**里可以改：

| 设置 | 作用 |
| :--- | :--- |
| 名字 | Bot 的资源名，也是设备页「HA 监听器」里显示的名字。同一家店有多个 Bot 时请分别起名。 |
| 启用 | 停用后 Bot 对所有命令只回复「Bot 已被店铺停用」，不再做任何事；重新启用后立即恢复。 |
| 玩家可用的命令 | `全部` 或 `只读`。只读时玩家只能绑定身份（`bind`）、查询（`wallet`、`billing`、`history`、`items`、`list`、`show`、`麻将列表`、`versions`、`api测速`、`ws测速`）、兑换（`redeem`）和延迟关机（`keep`）；入场、结账、上下桌和设备操作（`login`/`入场`、`logout`、`mahjong`/`上桌`/`下桌`、`lock`、`on`、`off`、`coin`、`scan`）只有店员能用，包括替其他玩家操作。 |
| 只读提示 | 只读模式下玩家使用受限命令时 Bot 的回复。 |
| 店员命令 | 店员可以替其他玩家入场、结账、查询，以及 `add`、`del`、`overwrite`。 |
| 关机仅限店员 | `off` 只允许店员使用（以店员身份越过入场要求）；`on` 始终只允许已入场玩家使用。 |
| 账单私聊店员 | 玩家退场或店员覆盖结账后，把同一份账单私聊给同一聊天平台上的店员。 |
| 闲置提醒频道、提前分钟 | 闲置自动关机的提醒发到哪里（Koishi 的 `平台:频道` 格式，如群 `onebot:群号`、私聊 `onebot:private:QQ号`），以及提前几分钟；0 或不填频道则不提醒。 |
| 门锁 | `lock` 打开的门（带门锁能力的资源）；店里只有一扇门时默认就是它。没有门时 `lock` 回复本店还没有设置。 |

**店员**是在这家店工作、并在网页里绑定了聊天平台身份的人：Bot 按「平台 + 账号」认人，`onebot:114514` 是店员不代表 `telegram:114514` 也是。**货币名称**取店铺的余额资产名，**麻将桌**和**门锁**取店铺的资源，都不需要在 Koishi 里重复填写。店铺没有开启计费时，入场、结账、钱包、上下桌、`list` 等计费命令直接回复「本店未启用计费」。

Bot 连上平台后先读取这些设置，再向平台打招呼；网页里改了设置、店员绑定了新身份、增删了麻将桌或门锁时，平台会通知 Bot 重新读取，**不需要重启 Koishi**。

旧版的 `autoRegister`、`currencyName`、`defaultDoorDeviceId`、`defaultScanProvider`（刷卡固定使用 Aime）、`loginPricingConfigIds`、`loginSessionLabel`、`enableStaffCommands`、`staffUserIds`、`powerCommandsAdminOnly`、`playerCommands`、`readOnlyNotice`、`logoutNotifyUserIds`、`idleNotifyChannelIds`、`idleReminderMinutes`、`watchHomeAssistant`（改由平台调度）、`botName`、`mahjongTableConfigs`、`mahjongTableSize` 已全部移除；升级后请到 Bot 的资源页重新设置。玩家首次使用时是否自动建档由店铺自己的注册开关决定。入场开始这个 Bot 在 PRiSM 里的计费方案：Bot 资源的专属方案，否则它所属资源组的方案；没改过的 Bot 在默认资源组，即店铺默认计费方案。已经在计费时 Bot 回复「您已在「方案名」中」。

### 统一平台

配置 `baseUrl` 和本店的 Integration 令牌后（店铺编号可选），插件先按凭据读出所属店铺，再与 PRiSM 只保持**一条 WebSocket 连接**（`/api/v1/shops/:shopCode/integration/ws`），所有命令都作为请求帧走这条连接，平台也通过它推送闲置关机提醒。连接断开时命令直接回复「操作失败，暂时连不上服务器。」，不排队、不自动重发；插件在后台自动重连。需要 Koishi 的 `http` 服务（`ctx.http.ws`）。不再支持不填 `shopCode` 的单店兼容部署。

玩家在网页取得验证码后，向任意已接入的店铺 Bot 发送 `bind 验证码`（旧命令 `prism.bind` 仍可用）。店家可以在 PRiSM「设置 → 玩家与身份 → 绑定提示」改写玩家看到的绑定提示。所有命令从消息的 `session.platform` 和 `session.userId` 读取身份，发送 `{ code, provider, subject }`，不接受手填或代填身份；`provider` 配置已移除。例如同一实例的 OneBot 和 Telegram 消息分别使用 `onebot:114514` 和 `telegram:114514`。群／私聊过滤交给 Koishi。网页账号可以跨店使用，平台验证、玩家和余额按店铺隔离；同一网页账号追加平台绑定时复用同一个玩家。

店主在 React「设置」控制是否要求平台身份，任意一个验证平台即可满足。默认开启；关闭后登录网页账号即可入场。已有标识不会自动改名，需店主在「平台身份转换」输入原标识与目标标识，预览冲突后主动执行，例如 `qq → onebot`。余额和账单不变，原标识若未转换，OneBot 新身份不会自动认领它。

统一平台以店铺的入场规则和注册开关为准。Web 与 Bot 普通入场共享去重；麻将桌由平台的桌位流程计费。店铺启用入场、出场或机器操作定位时，对应 Bot 操作会返回本店网页地址。玩家余额不足时结账失败并继续计时。

### 监听 Home Assistant

Bot 一直在线，所以平台会优先让 Bot 当店铺的 Home Assistant **监听器**：连上平台后 Bot 在握手里声明自己能监听，平台把 Home Assistant 的地址、一个**只读令牌**和要关心的设备实体发给它，Bot 订阅这些实体，把每次变化通过同一条连接报给平台。玩家页和商户后台因此能实时看到电源、空调状态，不必再临时去问 Home Assistant。店里的 HINATA IO 机台也能做同样的事；一家店同时监听的数量默认 2 个（由平台管理员按店铺调整），Bot 排在机台前面：一个 Bot 在线就占一个名额，两个 Bot 就占满，机台只补空位，Bot 上线时机台会在 Bot 交出完整状态之后让位，中间没有空窗。商户后台设备页的「HA 监听器」会显示现在是谁在监听。

- **谁在监听由平台决定**：能连上 Home Assistant 的 Bot 都会在 hello 里声明，平台按店铺的监听名额挑选和轮换；店家没有开关，也不能指定。不想要某个 Bot 参与，停用这个 Bot 资源即可。
- **地址**：平台给的地址列表按顺序尝试（店内地址在前、外部地址在后），不区分 Bot 在哪、Home Assistant 在哪，哪个通就用哪个。每个地址最多等 10 秒连接，一轮全部失败才向平台报断开，上次连上的地址下次排第一。
- **名字**：设备页显示的是 Bot 资源的名字，多个 Bot 请在资源页分别起名。
- 需要 Koishi 的 `http` 服务（`ctx.http.ws`），和与平台的连接用同一个。

## 📝 机器人指令列表

### 玩家指令
* `bind <验证码>` - 把网页登录账号绑定到当前平台身份（旧命令 `prism.bind` 仍可用）。玩家第一次绑定时是否自动建档由店铺设置决定，原来的 `register` 命令已移除。
* `login` / `入场` - 开启当前玩家的计费场次：开始这个 Bot 在 PRiSM 里的计费方案（资源编辑页「计费」一节设置所属资源组或专属方案）。
* `logout` - 结算当前玩家的计费场次。
玩家在未产生任何费用时退场，机器人会简洁显示“本次未产生费用”和当前余额；存在收费或优惠明细时仍显示完整结算账单。负单价 session 会在区间明细中保留真实的负数计费贡献，只有后端汇总全部 session 后的最终应付金额会限制为不低于 `0`。
结账成功回执中的余额为后端已经完成扣款后的余额；只有 `/billing` 预览会显示当前余额与预计结账后余额。
方案内区间封顶直接计入对应计时费用；全局封顶按后端返回的结构化日期和时段逐条列出，不合并、不截断，并直接形成计费总价，不作为优惠。只作用于整次结账的资产优惠直接列在计费总价下方，不显示额外标题或 emoji，也不会误归属到最后一个 session。
Bot 设置开启「账单私聊店员」时，玩家退场或店员覆盖结账成功后，机器人会把同一份账单私聊给同一聊天平台上的店员，账单会明确显示结账玩家身份。
同一玩家在前一次退场结账尚未完成时重复发送 `/logout` 或 `/退场`，机器人会复用同一次结账请求与账单，避免重复扣款。
账单和管理员代操作回执均使用“平台昵称（平台标识:身份值）”称呼玩家；平台暂时无法提供昵称时显示“未知昵称（平台标识:身份值）”，不会显示内部玩家 ID。
管理员 `/add` 增加免费余额；`/del` 按结账相同的顺序从可用免费余额、再从付费余额扣除，余额不足时会返回余额不足提示。
* `billing` - 预览当前玩家本场计费的消费费用。
* `wallet` - 查看当前玩家的钱包余额。
* `items` - 查看当前玩家持有的道具或资产。
* `list [资源或方案]` - 查看在店的人：正在玩（占用某个资源）或有任意进行中计费的人都算；刷了本店认不出主人的卡不算占用，`[总计 N 人]` 就是这个人数。每人只列一处：正在占用的资源下（显示当前人数和容量），否则列在最具体的计费方案下（例如同时计费「普通游玩」和依赖它的「麻将」时列在「麻将」）。带名称时只列这一项：资源名或别名列出上面的人，方案名列出所有在计费这个方案的人，例如 `list maimai`、`list 普通游玩`。
* `show [deviceId]` - 查看设备电源与连接状态。
设备状态按后端的普通字符串契约显示；插件仍兼容历史数据库中的 JSON 字符串状态，避免旧记录显示为 `unknown`。
* `history` - 查看自己的历史游玩记录。
* `lock` - 打开 Bot 设置里的门锁；TTLock 门锁会生成一个 8 位随机临时密码（有效期 3 分钟）并回复密码。
* `on <deviceRef>` - 使用后台设备名称、别名或 `all` 请求启动电源；仅已通过 `login`/`入场` 开启活跃计费 session 的玩家可用。不接受 Home Assistant entity ID，成功回复使用后端返回的设备名称。
* `off <deviceRef>` - 使用后台设备名称、别名或 `all` 请求关闭电源；与 `/on` 一样仅允许已入场玩家使用，不接受 Home Assistant entity ID，`all` 显示为“所有设备”。
* `keep <设备名或别名>` - 延迟闲置设备的自动关机。只对开着的设备有效，永远不会把设备开起来；需要玩家已入场。只读模式（`readonly`）下玩家也能用。
* `coin <设备名或别名> [count]` - 请求向后台配置的 Hinata IO 设备投币；需要玩家已入场。
* `scan <设备名或别名>` - 使用当前玩家后台绑定的 Aime 卡向设备刷卡，不在群聊中输入或显示卡号。
* `redeem <code>` - 兑换礼物码。
* `mahjong <桌号>` / `上桌 [桌号]` - 按桌名或别名（不区分大小写）坐上麻将桌；`/上桌` 未提供桌号时会引导查看 `/麻将列表`。不需要先入场：坐满时平台为全桌开始计费，已开局的桌补位后立即开始计费。满桌、已在别的桌，或平台拒绝计费（例如不在麻将计费时段）时回复原因。
* `下桌 [桌号]` - 离开当前所在的麻将桌（也可以指明哪一桌），正在计费的会停止计费，并显示该桌剩余人数。
* `麻将列表` - 查看店里麻将桌的桌名、别名，以及空闲、等位或游玩中状态。
* `api测速 [次数]` - 走 HTTP 连续查询自己的钱包：首次（含建立连接）单独列出，之后显示最小、平均与最大延迟，并给出服务端处理时间和经过的 Cloudflare 节点（默认 5 次，最多 10 次）。
* `ws测速 [次数]` - 走 Bot 的 WebSocket 连接：心跳往返（纯网络）和同样的钱包查询，并给出服务端处理时间（默认 5 次，最多 10 次）。两者对比可以看出延迟在网络还是在服务端，以及长连接能省下多少。
* `versions` - 显示当前 Bot npm 包版本和后端发布版本；后端不可达时仍会显示 Bot 版本。

Bot 版本直接读取本 npm 包的 `package.json`，后端版本读取无需认证的 `GET /version`。插件发布遵循 SemVer；修复使用 patch、兼容新增功能使用 minor、不兼容改动使用 major，发布前通过 `npm version <patch|minor|major>` 自动更新包版本。

### 店员快捷指令
Bot 设置开启「店员命令」后，店员（在网页绑定了当前聊天平台身份的店员）可使用：
* `add <target:user> <amount:number>` - 为目标用户增加余额。
* `del <target:user> <amount:number>` - 从目标用户扣除余额。
* `overwrite <target:user> <amount:number> [reason:text]` - 覆盖目标用户本次结账金额，并立即执行结账；未填写原因时使用默认管理员调价原因。

## 🛠️ 本地开发与构建

1. 确保已安装 Node.js 和 `bun`。
2. 克隆本仓库：
   ```bash
   git clone https://github.com/nerimoe/koishi-plugin-prism.git
   cd koishi-plugin-prism
   ```
3. 安装依赖并执行编译：
   ```bash
   bun install
   bun run build
   ```
4. 运行单元测试：
   ```bash
   bun run test
   ```

### 提交检查

`main` 和 PR 均运行独立的 GitHub Actions `checks`：Bun 类型检查、Bot 命令回归测试与 TypeScript 编译。设置读取、麻将上桌/下桌与多平台退场去重使用模拟平台和适配器测试，不对线上店铺写入。发布新 npm 版本后，还要确认运行中的 Koishi 实例已经升级。

### CI 自动发布

发布使用 GitHub Actions 的 npm Trusted Publishing。合并到 `main` 时，如果 `package.json` 的版本在 npm 上还不存在，就自动测试、构建、发布，并打上 `v<版本>` 标签；版本没变则跳过。所以发版只需在 PR 里改版本号：

```bash
npm version minor --no-git-tag-version
```

也可以推送与 `package.json` 一致的 `v` 标签，或在 Actions 里手动运行 `Publish to npm`。

首次使用前，在 npm 包设置的 Trusted Publisher 中选择 GitHub Actions，填写仓库 `nerimoe/koishi-plugin-prism` 和工作流文件名 `publish.yml`，并允许 `npm publish`。

### 平台身份绑定与查人验收

绑定支持 Koishi 提供的各适配器标识，身份值保持字符串，不限定数字格式。店员和账单私聊按「平台标识 + 身份值」认人，相同号码的其他平台不会继承权限或通知。管理员代操作使用目标平台标识，禁止通过当前适配器误操作另一个平台。`/list` 只用当前平台的身份查询昵称，缺失时使用后台名称。源码和 npm 发行包需要分别核对版本。

### 0.3.0

Koishi 配置只剩 `baseUrl` 和 `integrationToken`（`shopCode` 可选、已不需要）。Bot 在 PRiSM 里是一个资源，其余设置（只读模式、店员命令、关机权限、账单私聊、闲置提醒、门锁、名字、启用）都在商户工作台的「Bot 设置」里改，连接后读取、修改后由平台通知重新读取。店员改为网页里绑定了平台身份的店员，货币名称、门锁和麻将桌取自店铺。麻将改由平台完成（不必先入场，满桌开局），`下桌` 可指明桌号；`list` 按平台的在店名单输出（每人一处，资源带人数/容量），`list <资源或方案>` 只列这一项；下桌后回复还在计费的方案；入场开始 Bot 所在资源组的方案（或 Bot 的专属方案），重复入场回复「已在「方案名」中」，入场结束了互斥方案时列出被结束的方案。移除插件自己的麻将桌状态与所有旧配置项。需要配套支持 `integration/bot`、`integration/mahjong-tables`、`integration/roster` 和 `config.changed` 的 PRiSM（1.1.0 起）；店铺所在的 PRiSM 升级之前不要升级到此版本。

### 0.1.39

支持统一平台店铺 API、平台身份 绑定和麻将查人统计；兼容新版入场标签，修复已入场玩家无法通过 Bot 上桌的问题。

### 0.2.0

与 PRiSM 改为一条 WebSocket 连接通信，不再发 HTTP 请求；连接断开时命令直接失败。移除单店兼容模式（`shopCode` 必填）和插件自己的无人自动关机（`powerOffInterval`），改由 PRiSM 后台的「闲置自动关机」负责；新增 `idleNotifyChannelIds`、`idleReminderMinutes` 接收关机提醒，以及 `keep` 命令延迟关机。需要配套支持 `/integration/ws` 的 PRiSM。

### 0.1.41

移除手填平台标识；使用消息适配器身份完成绑定、计费和设备指令。支持同实例多适配器，绑定采用 `provider:subject`，员工权限和账单通知按平台隔离。需配套新版 PRiSM 的 `platform-binding` 接口；旧身份由店主主动转换。

绑定命令改为 `bind <验证码>`（`prism.bind` 保留为同义命令），移除 `register`（第一次绑定时是否建档由店铺设置决定）。新增 `playerCommands`：设为 `readonly` 时玩家只能绑定、查询和兑换，入场、结账、上下桌和设备操作仅 `staffUserIds` 中的管理员可用，玩家收到 `readOnlyNotice`（这些选项现已移到 Bot 设置）。

## 时间展示

账单、历史与资产到期使用 API 时间字符串所带的店铺偏移，例如 `2026-10-03T10:08:00+08:00`，不依赖 Bot 服务器时区，也不手工加八小时。账单注明 UTC 偏移；时间排序及游玩时长按绝对时间计算，兼容旧 `Z` 时间戳。网页／Swift 的个人时间可按玩家设备时区展示，因此跨地区使用时显示时钟不同，但时长和金额一致。
